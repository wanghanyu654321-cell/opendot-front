## R19–R23（2026-11-15 准入 R23）

R19–R23 围绕「待确认事项（挂起项）」收口：每个员工同一时间只挂一件；中途查询、闲聊不会把它冲掉；过期、被替换时给出明确提示；「对」只能确认员工已经看到的那一张草稿。

| D 号 | 摘要 |
|---|---|
| D171–D173 | 汇总词不当客户名；新客户追问未答又来新消息给提示；未见过的否定补报说法先问 |
| D174 | 每个员工同一时间只挂一件待确认事项，新报单替换并作废旧的 |
| D175 | 只有会出新草稿或新客户追问的消息才替换挂起项；查进度、闲聊、「入账结果」等都不清 |
| D176 | 挂起项过期后提醒一次，提醒完即清 |
| D177 | 跨店或代报在入口被拒，不算新报单 |
| D178 / D182 | 有挂起项时，凡不占挂起位的追问，末尾都提醒上一笔仍在等「对」 |
| D179 | 过期后的下一条消息（不论是否报单）就提醒 |
| D180 | 预约、改单、其他类型各用自己的过期话术 |
| D181 | 提醒一项一行；过期后问「入账结果」先照常回答再提醒；过期后回「对」只回过期原话 |
| D183 | 「对」只确认它到达前员工已看到的草稿；已被替换时不确认新草稿 |
| D184 | R22 之后只修会记错账或卡住员工的问题，文案放到上线后 |
| D185 | 新客户追问过期后回肯定词：不出草稿、不建客户，只提醒一次 |

R23 的实现要点：

- 草稿、追问和入站消息都从同一个 PG 序列取号，存储层只比较一个条件（挂起项序号 < 到达序号），内存存储等价实现；
- 迁移 011：按员工建、只约束 pending 行的部分唯一索引，保证每个员工最多一条 pending；D174 的替换和作废提醒在同一事务里完成；
- 过期结算、确认都是带条件的状态迁移，并发下「对」只入账一笔。
