## §2 金额与抽取根因（给复审）

**根因 1（R7-01「X姐 + 万」误伤）：** 金额函数与 `parsePureMoney` 在 R7 已能算出「1.2万」。误伤发生在员工循环里：`extractReport` 的中文金额片段把称谓后单独的「万/千」当成不确定金额，在 `tryStandardReport` / `parseLooseReport` 之前就提早追问。修法是循环与抽取**先走同一份语法**；称谓行里的万/千由语法一次算完。

**根因 2（多行「760」后下一行称呼被当约数）：** `guardUtteranceAmounts` 的 ARABIC 跨度用了 `\s*`，`\s` 含换行，于是「（评测原句已删）」的 span.end 已经落在下一行，「（评测原句已删）」检测看不到跨度内的换行，后缀走到「（评测原句已删）」，`sealDraftAmounts` 因收不齐已校验分值而 `unvalidated`（对外是「（评测原句已删）」）」）。这就是 R7 盲测相关评测条目掉下、以及门①锁定先失败的原因。修法两处一起做：ARABIC 只吃横向空白；`checkSpan` 把跨度里的换行裁掉，并把换行当硬分隔。行尾表情（😊）按装饰跳过，不计入约数后缀。

**根因 3（D123 与 Codex R7-02）：** Codex 希望「任何行尾备注都不要出可确认草稿」。产品 21:30 覆盖为：只有否定/取消**词组**才追问；「不错」「不用找」和其他普通备注出草稿并附原文。实现按产品。约数词仍追问。
