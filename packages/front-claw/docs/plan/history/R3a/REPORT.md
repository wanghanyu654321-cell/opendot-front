## §1 第 1 项：今天日期的标题报单——**原本就覆盖了，这次只补测试，没有改入口逻辑**

D81 的判定是 `if (report.businessDay !== today) return NOT_TODAY_REPLY`。标题「12号B店」「11月12日 B店」「11.12 B店」等，经 `parseHeader` / `resolveDayOnly` / `resolveMonthDay` 解析出来的营业日如果等于今天，就不会被拦住，照常出待确认清单，回「对」后入账。

修前证据：把新测试拷到 9ecf7052 干净树上跑，**11 条标题用例全部通过**（`test-output/prefix-r3a-unit.txt`：6 个失败全是第 2、3 项，标题用例 0 失败）。本轮在 `tests/r3a/r3a-header.test.ts` 补了：

- 单行，五种今天标题写法：「12号B店」「11月12日B店」「11月12日 B店」「11.12 B店」「11/12B店」——出清单 → 「对」入账
- 多行（本人 + 同店代报 + k/w 金额）：一次出清单，回「对」三笔全部入账
- 边界：昨天（11号 / 11月11日）、明天（13号 / 11月13日）、上月同日（10月12日）——固定回「目前只能报今天的单，补报请找店长」，零草稿零入账

变异 R3a-M4（今天的标题也被拒）、R3a-M5（非今天的照收）都被这些测试抓住。
