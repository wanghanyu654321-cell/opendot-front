## 做了什么

### D135 定稿
客套词表恰好是：谢啦、谢谢、谢了、辛苦了、麻烦了、麻烦你了、好的、收到。只有整段都由这些短语组成时才剥掉（可夹标点、可连续多枚）。「谢谢，不过没做」「不错谢谢」整段不是客套，一处都不剥，按备注走 D130。不再标「待确认」。不在词表里的「多谢」「感谢」不剥。

### R10-01（clauseKind）
删掉 `remarkForDraftPolicy` 里「`clauseKind(s) && k !== 'report'` 则返回空」的短路。标准行尾部剩下的内容，**不管 `clauseKind` 判成什么，都必须过 D130**。只有确定匹配到的归属、复合、客套才剥；剥不干净的（「帮写个朋友圈文案」「查一下库存汇总」「谢谢，不过没做」）一律追问，不出草稿。归属匹配加了边界，避免从「不算我的」里掏「算我的」。

### D137 / R10-02、R10-04
金额后紧贴、无括号的归属：`算/记/报/登我的（名下）` 记给报单人；`报 X 的`、`记 X 名下`、`帮/替/给 X 报（上）` 从归属取员工并核对本店。与括号冲突则追问。自编 20+ 变体（钱姐、周老师、孙姨、吴哥）。「登记」不当成「登+记」，避免把「（评测原句已删）」误读成员工名。

### R10-05、相关评测条目
连接词补上「顺带」，句读后若前半是报单、后半确定是另一件店务才拆（同一件预约「（评测原句已删）」不拆，避免丢掉钟点）。已认出完整报单时，不单独走改账把报单丢掉：报单出草稿，改账由 leftover 明说没办（并写明前半句已进待确认）。相关评测条目仍在锁定 ID 里，本轮仍出草稿。

### R10-06
在同一份语法里推广「不是（在）补（报）（昨天/前天/上周的）」：报单本身是今天时，否定补报里的日期不触发 D124；该短语本身从备注里剥掉，不当 D130 残留。金额后缀 **元整、块整、整** = 元，写入 `AMOUNT`、`parsePureMoney` 和 amount-guard（快通道与收口都认）。各 10+ 自编变体，不是单句修补。

### R10-07
`customerOf` 拒绝把动词或时间词（过来、到店、开始、来做、明天、下午等）当客户名。点不出名字则 `customerNamed=false`，入口追问称呼。写了周老师/张三仍收下。

### D136 新口径
分母 = 归属和复合（以及整段客套）剥掉以后仍有剩下备注的标准行；没有剩下的，分母分子都不计。分子按最终 `outcome === 'clarify'`，且剩余备注不在白名单（不只认固定句式）。门槛 ≤5%，超了在摘要标明「超过5%」。被追问的备注按白名单类别计数，没有类别的给原文片段。不往白名单加词。
