## 改动内容（相对 c6a583af，23 个文件，+713/−118）

全部判定都收在 D152 单闸（confirmable-draft-gate.ts）里，唯一出口和结构测试没有变。

1. **带员工括号的客户位从严（D165/D139/D153）。**
   - 带括号和不带括号走同一套判定：先 D163，再 D139 三档。
   - 三档是：非名字词或残片 → D153 通用追问；已知客户 → 出草稿；其他名字 → 「是新客户「X」吗？」，不附草稿，回「是」后再过一次闸。
   - 第 3 轮补了一条底线：不在名单里的开放名字，必须是「配置单姓/复姓＋1–2 字名」或「昵称前缀＋1 字」，才进入「问是新客户」那一档；否则走通用追问，回「是」也绕不过去。
   - 这样，表外前缀紧贴一个陌生名字时，不会被问成带前缀的新客户。
   - 第 2 轮删掉了第 1 轮那个写死具体词的前缀黑名单。
2. **没见过的否定补报：** 按结构泛化。否定词后面同一分句 8 字以内出现「补报/补记…」或过去日期词，就判为非纯标准行，先问。
3. **D161 分号清单：** 每段单独过 standard-line 口径的 amount-guard 和单闸。客户、自报标记、复合残片都取本段原文。任一段不过，整条先问，不出半张清单。全过时 source_ordinal 等于段序号。
4. **D162：** ① 有待确认草稿时，「对」就是确认新草稿，标记挡不住；② 标记跟那一笔的 expiresAt 一起过期，过期即清掉。只在没有待确认草稿时才读标记，PG 并发路径没有多加读写。
5. **D163 保留：** 原客户位（归一之前）有空白或【】[]，就拒收先问。
6. **D164：** 标签表加了报数、报个数、今日报数、今天报数，配置仍是 frozen。【…】只有在括号里是表内标签，或能按 D101 解析成日期/店名抬头时才剥；否则先问。
7. **D165：** 先剥表内前缀，而且前缀后面必须有冒号、逗号、空白或换行，再判客户位。表内标签紧贴客户位、没有分隔的，整条通用先问。表外前缀先问，草稿客户位不会带前缀残留。
8. **D166：** 行尾独立的表情忽略；表情夹在客户名或金额中间，先问。
9. textLevelImpurity 的 today 改成必填，去掉了写死的默认日期。
