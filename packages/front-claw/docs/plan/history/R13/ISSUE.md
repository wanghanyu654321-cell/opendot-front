# R13 问题（按描述，不写助手B的原 ID 编号以外已公开的 R12-01 / R12-02）

## R12-01（P1）

不带括号、也不是「姓＋称谓」的名字，仅靠 `NOT_CUSTOMER_NAME` 黑名单判断时有结构性缺口：时段（上午、全天、本旬、今早）、泛称/泛指人称（每人、大家、各位、我本人、咱们）、量词（一位、两个）等会被当成客户名并直接出可确认草稿。产品负责人在 D139 修订中选定默认政策 **C**：不以继续扩黑名单为主策略。

- 命中 `NOT_CUSTOMER_NAME`：追问，不出草稿。
- 本店已知客户（已有订单、预约，或今天已报单，整词匹配，只用现有数据）：直接出草稿。
- 其它名字：只问「是新客户「X」吗？」，不附任何可确认草稿；员工回「是」以后才出草稿，草稿仍要回「对」才入账，该名字从此进名单；回别的则不出草稿、不写入。

A、B 保留为可切换配置（D140）：A = 一律先问；B = 正向格式（百家姓＋1–2 字，或小/阿/老＋1 字，外加冲突表）。默认 C。切换到 A 只改 `config/customer-name-policy.json` 的 `mode`。

## R12-02（P2）

报单草稿回显不展示客户名，员工难以核对。所有报单草稿须单独一行显示「客户：X」（无客户名时「客户：（未写）」）。

## 评测

离线种子带历史客户名，用标准行种子写入上一营业日已确认行；REPORT 写清定义。新客户首报追问从门①分母拿出单独报数。REPORT 分别报 A、B、C。D131、D137 不回退。不读盲测留出集与任何复审记录。
