## 做了什么

1. **所有报单草稿单独一行「客户：X」**（R12-02）。无客户名时「客户：（未写）」。
2. **`customerNamePolicy` + 本店已知客户推导**，配置 `config/customer-name-policy.json`（**`mode` 默认 `"C"`**）。A、B 可切换。只作用于「不带括号、也不是姓＋称谓」的名字；判定在员工入口、完整解析之后，不缩小语法。
   - **C（默认）**：① 命中 `NOT_CUSTOMER_NAME` → 追问、不出草稿；② 本店已知客户 → 直接出草稿；③ 其它名字 → **只问「是新客户「X」吗？」**，不附可确认草稿。员工回「是」后才出草稿，草稿仍要回「对」才入账。回别的（含「对」）→ 不出草稿、不写入。
   - **A**：上述范围内一律先问。**B**：正向格式（百家姓＋1–2 字，或小/阿/老＋1；冲突表 周末…周五、全天）通过则直接出草稿，否则同上追问。
   - **切换到 A**：只把 `config/customer-name-policy.json` 的 **`mode`** 改成 `"A"`。
3. **D139 补充（本轮修订，取代「回是就进名单」）**：
   - 新名字 **只有在该单回「对」、已经确认入账之后**，才算本店已知。只回了「是」、草稿未确认，或草稿后来作废、超时、被放弃的，名字都不进名单。
   - **已干脱「记住名字」单独状态**（无 `rememberCustomerNames`、无 `customer-roster:accepted` 配置键）。已知客户 **只从现有数据推导**：
     - 本店 **已确认** 订单（`listEntries({ storeId, status: 'confirmed' })`，任一营业日，含今天已确认的报单；`voided` 作废不算；并再校验 `storeId` 与 `status`）；
     - 本店预约的客户名（`listAppointments({ storeId })`，同样校验本店）。
   - **「今天已报单」只算已确认的**：未确认的报单草稿不再计入名单（此前实现把 pending 草稿也算进去了，已改掉）。
   - **名单严格按本店隔离**：别的店已确认的客户名，在本店不算已知，仍要问「是新客户」。
4. **D131 口径保持不变**（不走名单模块）：
   - D131 仍只看 **本店、今天、已确认** 的账本行：`listEntries({ storeId: actor.storeId, businessDay: report.businessDay, status: 'confirmed' })`，再过滤 `status === 'confirmed' && storeId && businessDay`。
   - 不含未确认草稿、不含其它店、不含其它营业日、不含作废单。
   - 因此：回「是」+「对」入账后，**同一天**再报同名仍走 **二选一**（可确认的选择草稿，不是「是新客户」追问）；**隔日**再报则名单已从上一营业日已确认单认出，且不占今天 D131，**直接出普通报单草稿**。历史标准行种子写入 2026-11-11，同样不触发今天的 D131。
5. **历史客户名标准行种子**：一条种子等价于在上一营业日 2026-11-11 用标准行「客户名：金额（员工）」报入并回「对」之后的已确认记录，经 `insertEntries` 写入，不走今天的员工入口。冻结名单见 `tests/r13/fixtures/historical-customers.json`（产品点名五人 + 锁定集解析出的客户名）。
6. **门①**：新客户首报追问从分母拿出单独报数。门②以可确认草稿为执行。
