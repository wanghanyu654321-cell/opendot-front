期望可观察行为：报数、进度、确认、闲聊等不会被提交到营销岗位；只有明确营销意图且营销能力已启用并获权才进营销；歧义或多意图先澄清；每个请求在统一截止时间内有唯一终态，结果未知可按原操作号查回。

## 3. 本次范围（可独立验证）

- [ ] 规则快路径分类：报数/确认跟进/进度/入账结果/预约/汇总/闲聊/营销/未知；多意图与歧义→澄清。分类器不持有 store，不写库。
- [ ] 路由决策：营销仅在“明确营销意图 ∧ 营销已启用 ∧ 获权”时进入；“帮我写今天报数清单”归店务。
- [ ] 至多一次受限语义分类端口（可选，默认关闭）：有截止时间、取消、畸形输出→澄清；不允许写库。
- [ ] 员工入口外层：统一截止、唯一终态（completed/failed/timeout/cancelled）、同请求号最终回复只投递一次、迟到结果只记录不再投递；结果未知回复带原操作号。
- [ ] route 日志：requestId + stage(inbound/classify/commit/deliver) + 毫秒 + 结果，不记录正文。
- [ ] 岗位对话：auto 选岗不再回落营销；店务/闲聊文本不提交营销岗位。
- [ ] 同店代报：清单括号内为同店在职员工→草稿与入账记给该员工，reporter 记为发送人；跨店（门店名或员工不在本店）拒绝且零写入。草稿项摘要防篡改。
- [ ] ≥100 条中文标注语料，调参集/盲测集分开，报宏 F1、澄清率、混淆矩阵；店务误入营销=0。
- [ ] test:pg 程序路径可由 FRONT_CLAW_PG_BIN 覆盖（默认值不变）；真实 PG 集成用例：M01 确认前不入账、重复确认不加账；M02 同店代报、跨店拒绝；两独立连接并发确认只入账一次。

## 7. 验收与故障场景

- 正常：报数→回显→对→入账一次；同店代报业绩记括号员工；营销明确+启用+获权→营销端口。
- 拒绝：跨店代报零写入；营销未启用/未获权→解释不写库；歧义/复合→澄清不写库。
- 故障：处理超时→唯一终态 timeout 且结果可按操作号查；迟到结果不重复投递；畸形语义输出→澄清；单请求失败不影响下一请求。
- 回归：M01 两个测试文件、相关回归、全量 vitest（已知 live-model-smoke 2 失败）、tsc、build。
- 真实性：MemorySql 替身 / 本机 PG17 临时集群分列；真实模型、企微、线上 PG 未验证；时延仅本地替身数据，不标达标。
