# R14 ISSUE（高档）

基于 R13 树 `d0cd0c8e2e8bf74fc3a64df2f41c45414227b5f5`。只修下列三项；D131 判定与 `scripts/eval-gates.sh` 回放逻辑不动。

## 1. 复合请求里的进度/查询被当成备注

一句里同时报单并询问本人进度时（报单动词残片 + 「再/另外」+ 查进度），进度说法会留在行尾备注里，被 D130 当成非白名单备注：草稿带错备注，或绕到「行尾备注需要确认」。延续 D134 / R11-03：拆分后进度部分走查询，不进备注。报单指令残片（「报一下」等）也不是备注。

## 3. R13-01 否定补报短语被带进客户名

「不是补报 / 不是在补 / 不是补的」这类否定补报短语，在客户名抽取前未被剥离，会进客户名。应先剥离再抽取；补单测和变异。

## 4. R13-02 过期草稿关不掉、会话卡住

过期草稿名字不进名单是对的。但回「对」只提示已过期、不关闭；回「取消」同样关不掉；随后新消息被「请先确认或取消当前草稿」挡住。要求过期后能显式取消或自动关闭，新消息能正常进入下一笔。补测试（含 PG）。

## 回归保护（现实现正确，不得改坏）

- D131 二选一已挂起时，员工回「新增一笔」：出一笔可确认的新报单草稿，金额用刚才再报的那笔。
- 没有挂起二选一时回「新增一笔」：回复「当前没有待选择的新增或改单。没有写入。」
