## §2 实现要点

### 2.1 R3A-01 更正匹配（以本轮转向说明为准，覆盖先前「客户+金额」说法）

- 在今天、本店、该报案人的已报记录中，用**客户名 + 营业日 + 报案人**过滤。
- **恰好一条**：进入并排待确认（原客户 / 原金额 / 原报时 vs 新金额），回「对」才写。用户若同时说了原金额：相符则作为附加确认，**不符则拒绝并说明原因**，零写入。
- **零条或多条**：列出今天已报（编号），请员工回「改 N」；**不要直接拒绝了之，也不按相近金额或近义名挑选**。「（评测原句已删）」不带原金额，在唯一时必须能用。
- 「改 N」是选定，不是入账：改写待选草稿为真正的更正草稿，再出并排确认，仍需「对」。在待选态回「对」**不得提交**。
- `parseNamedCorrection` 认「把 / 我今天已报 + 称谓 + 可选原金额 + 那笔 + 改成」；`parseCorrectionPick` 认 `^改\s*([1-9]\d?)`。分类器把「改 N」判为更正；员工入口在 ASK_KEY 或「改 N」时，即使分类是澄清也送回店务循环。

### 2.2 R3A-02 补偿

- `revertIfCurrentHolder`：Memory 与 PG 都只在本消费者仍持有租约（owner+epoch+until）时，才把 confirming 退回 pending。
- PG：`fencedWriteIn`（在已有事务内比围栏），`UPDATE … AND status='confirming'` 且租约 `EXISTS`；`FencedWriteRejected` → false，不抛到外层当成功。
- `commitConfirmingDraft` 围栏失败时调用上述复位；`closeConfirming` 关单失败后若已复位或围栏仍在，返回 -1（避免「0 行 = 无认领成功」）。
- 调度器通知领取 / 状态迁移仍走既有围栏令牌，没有另开不受检的写路径。
- 遗留 confirming：前任不是当前持有者、无法复位时，现持有者回「对」走 `finishAny` 继续入账，回「取消」作废草稿。这是补偿「不得误伤后任」的配套，避免 B 被卡住。

### 2.3 R3A-06 写路径与权限

- 静态收集 `collectWriteSql`：大小写不敏感；模板字符串按行展开，避免方法错位。未登记的小写 / 混合大小写 INSERT/UPDATE/DELETE 测试会失败。REGISTRY 将补偿登记为 `consumer_fenced`。
- **请注意：静态检查只是辅助。真正的守卫是数据库权限**——台账表只允许经入口语句写入，与 D46 最小权限账户同一原则。应用层静态清单不能代替角色授权。
- 已在临时 PG17（`127.0.0.1:55432`，`FRONT_CLAW_PG_BIN`）上做最小权限演示（`tests/r4/r4-privilege.integration.test.ts`）：只读角色对 `performance_*` 的 INSERT 被拒绝；经入口的写角色可完成入账。不是生产账户迁移，但是同原则的可重复证明。生产环境落实 D46 仍见 §5。

### 2.4 往日 / 模糊 / 复合 / 路由

- 往日短语含「昨儿/昨日」及不把 `.` 当日期分隔的显式日期（ISO / 中文 / 斜杠）。金额须带「元/块」或「称谓+数字」紧邻，避免「（评测原句已删）」「12号…1.2k」误判。
- `extractReport` 只在复合句**尾部是另一种子句**时取头部，避免「蒋姐剪发预约」被当成缺金额的报单，也避免整句被 OTHER_DAY/CORRECTION 吃掉报单半句。
- 模糊金额判定在歧义解析之前，所以「大概八百」是 `vague_amount` 而不是仅仅「说不清」。
- leftover 前缀保持 R3 既有句式「后半句「…」这次没有办」，以便原测试精确匹配。
- 全店查询「还有谁没报|列名单」即使没有「查/看」也算查询；但金额短回路始终优先，故「（评测原句已删）」「（评测原句已删）」仍是报单。r2 语料 ① 在补此短回路后为 30/30。
