# 分层回退

每层变更前保存旧配置与版本，核对快照和控制台恢复入口。脚本默认预览；实际操作需在授权维护窗口执行，不用历史合成测试代替验收。

## 主机

host.sh 只检查已装 Docker 和 Compose，不安装或改变主机。若人工升级造成异常，由运维按原快照恢复主机配置与原版本，再检查 Docker、磁盘、SSH 来源规则及控制台通路。不要直接执行未经核查的卸载或镜像/卷清理。

## PG

先停业务写入并备份。旧镜像兼容当前 schema 时才可直接回退；不兼容则恢复到新库，比较所有表的行数和哈希，核对恢复时点后的业务差异，经授权再改连接并重启。保留源库和原卷，不自动执行结构降级。回退不删除已持久化的去重事实或账本。

## OpenDot 核心

运维指定 CORE_ENV_FILE 与 ADMIN_ENV_FILE，DEPLOY_DIR 默认通用部署目录。先预览 rollback.sh，再经授权显式应用。脚本读取 previous，先停旧核心、确认无运行容器且 PG 消费租约已释放或已过期且超过十秒宽限，再启动旧 SHA 镜像并等健康；成功才交换 current/previous。缺状态、缺 previous、格式损坏或无效 SHA 均明确提示、退出 2，无栈追踪。健康失败也先停旧并核查，再恢复原 current，状态不推进。上线前保留两份镜像，不依赖现场重建。

完整 OpenDot 宿主另行保存旧镜像与挂点配置；回退宿主先关闭本次入口并优雅 close，再启动旧宿主。standalone 的装配与测试不能证明完整宿主已恢复。

## 主站

本交付不提供主站入口。若后续另行接入，变更前保留原主站版本及访问配置，失败还原原服务并核验登录与同一事实读取，不改账本。未装配时不虚构成功回退。

## CRM / 只读登录

本仓库没有这两项 Web 实现。后续分别保留原身份和岗位授权；失败还原各自原版本、撤掉新入口和会话，核验原授权与只读上限。新渠道不能获得原先没有的工具、门店或审批权限。

## 企微长连接

先停新单实例并等待 close 释放租约，确认容器、租约与在途发送状态，再恢复旧单实例。异常退出留下有效租约或刚过期不足十秒时拒绝接管；过期超过十秒后可重新核查并接管，损坏记录始终拒绝。脚本仍先核实旧容器已停止，无双开。msgid 去重继续使用 PG 历史事实，不能清库后重放；业务提交、投递和平台回执分别核对，未知结果不盲目补发。本交付没有真实连接或手机实收结论。

## 真模型

默认安全桩。真实模型配置变更须另行授权并保留旧配置，失败恢复经验证的旧配置或切回安全桩，按单消费者顺序重启。模型仍不能绕过统一确认闸、金额守卫或实时授权，标准行快通道不依赖模型。恢复后单独验收，不以历史门①、门②计数代替。
