# 产品

## 1. 用户与场景

美业连锁门店。员工、店长、老板都在企微里**私聊**机器人，不需要打开 Web 就能完成报单、确认、查回和预约。首轮试用定在 B 店，用一个测试账号（文档中称「测试员工A」）逐级降权来测。

## 2. 角色与权限（D5，hanyu 11-12 12:12 定）

| 能力 | 员工 | 店长 | 老板 |
|---|---|---|---|
| 报单（先确认再入账） | 本人；可代本店同事报，业绩记到括号里的员工名下 | 同员工 | **不能报单** |
| 跨店代报 | 拒绝 | 拒绝 | 拒绝 |
| 修改报单 | 只能改自己的 | **可改本店的**（留审计） | 只看 |
| 查业绩 | 本人 | 本店全员 | 名下门店 |
| 设月目标 | 不能 | 本店 | 只看 |
| 预约 | 登记即成立 | 收到提醒，不强制回复 | 不提醒 |
| 营销内容生成 | 暂不开放；以后按企微 ID 单独授权 | 同左 | 同左 |
| 30 分钟未确认提醒 | 发给报单人 | — | — |
| 积压告警（D40） | — | — | 只发给项目负责人 |

授权分层：企业 → 门店 → 角色 → 个人 capabilities。降级或停用后，已排队的待确认和任务在执行前按当前权限重查。

## 3. 报单规则（要点）

- **只认今天的单**（D81），暂不开放补报；非今天的回一句「只能报今天的单」（D124）。
- **标准行**：「客户：金额（员工）」及常见变体；不带括号的记给报单人（D102）；「X姐」称呼、中文万/千金额、多行格式都走快通道（D125）；不带括号的 2–4 字名字也算（D138）。
- **先确认再入账**：草稿单独显示「客户：X」一行，员工回「对」才入账；同店同日已有这位客户的单时，二选一「新增一笔 / 改第 N 笔」（D131）。
- **客户名单**（D139）：只算本店已确认入账的订单和本店预约，不跨店；新客户先问「是新客户「X」吗？」，不附草稿。
- **拿不准就问**：模糊金额（「六百多」）、行尾备注不在白名单（D130）、否定或取消说法（D123）、没见过的「不是补报」类说法（D146/D148）、客户位残片（D147）、非名字（D153）——一律先问，**不出可确认草稿**。
- **单闸**（D152）：可确认草稿只能来自纯标准行，或线上模型分类结果；离线桩永远不放行。
- **复合请求**：「报单＋查本人进度」的产品目标是两件都办（D130 b），由模型路径在正式实测中实现；离线时整句先问。改账、预约、宣传与报单组合时，报单照常出草稿，另一半明说没办。
- **过期草稿**自动作废，回「对」得到「这笔已过期，请重新报。（未入账）」（D143）。
- **确认只回一次**：并发重复回「对」只入账一笔、只回一次「已入账」（D151）。

## 4. 业绩口径（参考门店常用的第三方美业系统，见 [PERF-RULES-v1.md](PERF-RULES-v1.md)）

- 员工私聊报的单记为**开单业绩**；只计已确认的单。
- 基数是**折后实收**，赠送不计入；金额精确到 0.01；**没有单笔上限**，也没有大额二次确认；负数或 0 先问。
- MVP **不做耗卡、共创人、多人分配**。
- **完成率 = 当月已确认开单业绩 ÷ 门店月目标**，**不封顶**。

> 规则本身已完整写在 PERF-RULES-v1.md；第三方系统的参考材料不在本仓库。

## 5. 门禁（准入与正式实测）

| 门 | 含义 | 线 | 何时判 |
|---|---|---|---|
| ① | 格式清楚的报单直接出草稿 | ≥ 95% | 离线 + 正式实测。分母口径 A/B 待 hanyu 定 |
| ② | 该澄清的不执行（出了可确认草稿就算执行） | = 0 | 离线 + 正式实测 |
| ③ | 格式明确的查询直接办 | ≥ 90% | **只在正式实测**（离线不接真模型，hanyu 11-12 20:56 定） |
| ④ | 延迟：快通道 p95 ≤ 1 秒，模型分类 p95 ≤ 5 秒，模型超时 8 秒即追问 | — | 只在正式实测 |

门① 待定的两个口径：A＝全部格式清楚的报单；B＝只算纯标准行（D144 快通道）。另外，新客户首报的追问是否从门① 分母里单列。
